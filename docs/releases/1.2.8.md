# Runtime 1.2.8

Update `sympress/runtime` with Composer and review the resulting lockfile.

The environment reader changed, so the generated parser payload has a new
fingerprint. Run `vendor/bin/runtime` (or `composer install`) to regenerate the
configuration, ship the new `var/runtime/<fingerprint>/` directory with the
release and keep the previous one until rollback is no longer needed. Rebuild
deployment dumps with `vendor/bin/runtime dump-env <environment>`; existing
`.env.cached.php` files are replaced on the next request.

Values the web server places in `$_SERVER` under CGI meta-variable names
(`REQUEST_URI`, `QUERY_STRING`, `REMOTE_ADDR`, `SERVER_NAME`, `HTTPS`, …) and
under `HTTP_*`, `REDIRECT_*` or `PHP_AUTH_*` are no longer read as configuration
or interpolation sources. A project that relied on one of those exact names must
supply it through the real process environment or `$_ENV`. Other names passed
through `fastcgi_param` or `SetEnv` are unaffected.

Within one request the reader now samples each process variable once. Code that
calls `putenv()` after the configuration booted and expects the new value from
`sympress_runtime_getenv()` in the same request must read `getenv()` directly.

`doctor --production` adds `production.env-dir-readonly`: with a deployment dump
the environment directory must not be writable by the PHP runtime identity. A
deployment that still lets PHP-FPM write there now fails the strict gate; make
the directory read-only after `dump-env`. The standalone CLI reports version 1.2.8.
