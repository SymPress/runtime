# Runtime 1.1.0

Runtime 1.1 fixes command discovery in the standalone CLI. `list` and `help` now
use Symfony Console instead of being interpreted as setup step names:

```sh
vendor/bin/runtime list
vendor/bin/runtime list --format=json
vendor/bin/runtime help doctor
vendor/bin/runtime help run
```

These commands do not run setup, load project providers or recover package layout.
They work before WordPress is installed and when Runtime setup configuration is
invalid. A valid project Composer manifest and installed dependencies are still
required. Native `wp runtime list` and `wp runtime help doctor` use the same commands.

## Upgrade from 1.0

The existing `^1.0` requirement allows this release. Update in a build or branch,
review the lockfile and generated changes, and commit the reviewed result:

```sh
composer update sympress/runtime --with-dependencies
vendor/bin/runtime --version
vendor/bin/runtime list
vendor/bin/runtime validate
```

There are no configuration or persisted-format migrations. Existing direct step
selection, such as `runtime index wpconfig`, remains supported. `--list-steps`
continues to list configured setup steps; `list` lists Console commands.

If a custom step is named `list`, `help`, `completion` or `run`, use
`runtime run <step>` or `runtime -- <step>` to distinguish it from a Console
command. To exclude such a step, use `runtime run --skip <step>`.
See the [command reference](../cli.md) for all options and the
[1.0 guide](1.0.0.md) for installation and upgrades from older releases.
