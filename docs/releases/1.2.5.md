# Runtime 1.2.5

Update `sympress/runtime` with Composer, review the lockfile and regenerate the
managed configuration with `vendor/bin/runtime --no-interaction`.

For a `public/wp/` core layout, the main configuration now lives directly in
`public/wp-config.php`. WordPress loads it natively from the core's parent;
the root configuration and public forwarding loader are no longer required.
WP-CLI, section editing, setup drift and production diagnostics use the same
configuration target. Explicit alternate targets and compatibility profiles
remain supported.

Migration recovers literal authentication keys and salts from an existing managed
native root configuration without executing it. The previous root file remains
available for rollback. After verifying WordPress bootstrap and the preserved
salts, archive that file outside the public website before removing it from the
project root.

Customized sections, dynamic salt providers, location-dependent salt code and
root symlinks require explicit migration. These cases fail before generated
configuration is changed. Literal edits to the managed salt section remain
supported. See the [compatibility migration guide](../compatibility.md).

The standalone CLI reports version 1.2.5.
