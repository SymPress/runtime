# Upgrading to Runtime 0.2.0

Version 0.2.0 adds production diagnostics, deployment drift checks, download pins
and crash recovery. PHP 8.5+, Composer 2.10.3+ and the reviewed Composer library
line remain required. Read the [changelog](../../CHANGELOG.md) for the full list.

## Update the package and command paths

Change shell scripts and CI jobs from `vendor/bin/sympress-runtime` to
`vendor/bin/runtime`. The old executable is no longer shipped. Composer commands
such as `composer sympress-runtime` and configuration keys keep their names.

Update in your development or build environment, review the resulting lockfile
and generated files, then deploy that reviewed build:

```sh
composer require sympress/runtime:0.2.0 --no-plugins --no-scripts
composer install --no-interaction
vendor/bin/runtime validate
vendor/bin/runtime --no-interaction
```

If deployment uses a prebuilt environment dump, rebuild it for the intended
environment before deployment. Do not distribute a development dump to production.
Keep the referenced `var/runtime` payload with the generated configuration as
described in [Deployment](../deployment.md).

## Review native defaults

- Environment caching defaults to `auto` and invalidates on source path, size or
  modification-time changes. Production dumps remain immutable until rebuilt.
- `composer-managed: auto` disables dashboard file modifications and automatic
  updates in staging/production through the generated section. Existing constants
  take precedence; explicitly configure `false` if updates are managed elsewhere.
- Native URL downloads create `sympress-runtime.lock`. Review and commit it, and
  use `--update-lock` deliberately when changing downloaded artifacts.
- Native `db-check: health` no longer scans every table during setup. Schedule
  `vendor/bin/runtime doctor --database-health` explicitly; `--quick` is available.
- Doctor requires explicit `WP_HOME` in staging/production. Its production profile
  requires HTTPS and reports opaque bootstrap code or unproven permissions as
  unknown, rather than certifying them.

Compatibility profiles retain their documented defaults. The generated-file mode
still defaults to `0600`; use `generated-file-mode: "0640"` with appropriate group
ownership when deployment and PHP run as different users.

## Establish deployment checks

Run setup successfully before using `--check` or `--dry-run`: drift detection needs
the generated baseline. Custom setup side effects can produce an unknown result.
Use [production operations](../operations.md) for deployment gates, typed required
variables, mounted secrets, names-only environment comparison and pruning.

Interrupted supported package moves now recover through a private journal.
Keep pending journals and owned backups intact until recovery completes. Pruning
retains active payloads and refuses unknown ownership or pending recovery state.
The supported layout boundaries remain documented in [Deployment](../deployment.md).
