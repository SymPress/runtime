# Release 1.1.4

Native runtime caches support interpolation from real process variables through
Dotenv-produced substitution templates and salted dependency fingerprints.
Derived process bytes remain outside persisted values. Unchanged cache hits
resolve templates without loading the dotenv parser; changed, newly set or
removed dependencies invalidate the cache and reload the file chain.

Dotenv still interprets quoting, escaping and defaults. Typed values, appended
overrides and explicit reader writes retain their normal behavior. Independent
and bundled generated bootstrap payloads include this support. Cache files keep
the configured private mode (0600 by default, optionally 0640).

Deployment dumps still refuse external-variable interpolation. Sources with
command substitution involving external dependencies remain ineligible for
persistence, as do process-derived environment selectors whose values would
otherwise enter persistent metadata. Regenerate the managed Runtime payload during deployment so normal
producer validation reloads caches created by an older payload. Rebuild deployment
dumps through the existing release workflow when changing deployed configuration.

Focused regressions cover warm cache hits without parser loading, changed and
missing process values, appended-file chains, parser quoting/defaults, explicit
writes, command overrides and exclusion of process secret bytes. Hosted release
verification and registry publication are separate delivery steps.
