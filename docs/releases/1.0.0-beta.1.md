# Runtime 1.0.0-beta.1

This prerelease prepares the 1.x compatibility contract.

## Upgrade from 0.2

Keep the executable name `vendor/bin/runtime`. Use an explicit prerelease version
while evaluating the contract, and commit both `composer.lock` and the reviewed
`sympress-runtime.lock`. Keep a previous deploy with its own generated payloads
available for rollback.

The package requires PHP `^8.5` and Composer library `^2.10.3`. Kernel and QA
development dependencies now use stable tags, and the published manifest no
longer contains a local path repository.

Review [the public API](../api.md) when maintaining extensions. Only documented
`@api` members are covered by the 1.x promise. Existing internal methods are not
removed by this release. Custom `PhpTool` implementations can be executed through
the public process factory. Legacy adapters remain functional throughout 1.x and
are scheduled for removal in 2.0; see [Compatibility](../compatibility.md).

Native `wpcliconfig` now adds the `wp runtime` command, available before WordPress
loads and without a kernel. It uses the standalone command implementation in a
child process. Existing user-owned YAML is retained. Review its entries before
regenerating with `vendor/bin/runtime --force wpcliconfig`, or add the documented
[registration entry point](../wp-cli.md). Legacy profiles retain their YAML
unless you opt in manually. Composer also accepts `composer runtime` and aliases
such as `composer runtime:doctor --json`.

Download locks gain an additive `format: 1` field while retaining `version: 1`
for 0.2 readers. Existing pins remain valid. Unknown future environment formats
are rejected before cache invalidation or overwriting. See [File formats](../file-formats.md).

Regenerate managed outputs, review the resulting changes and refresh the setup
baseline before using `--check` as a deployment gate. Do not discard an active
payload or build dump during the upgrade. Public site URLs and web-server routes
are project-owned and are not changed by the release.

The [compatibility policy](../compatibility-policy.md) covers all 56 existing
schema keys, CLI behavior, environment controls, hooks, sections and formats.
The [platform table](../platforms.md) states the limits of the operating-system
tests. Use the CI run for the tagged commit as the authoritative test result.
