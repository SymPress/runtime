# Runtime 1.0.0-beta.2

This bugfix prerelease addresses installation into an empty Composer project.
Beta 1 downloaded and installed successfully, but its automatic setup then failed
because the project did not yet contain WordPress Core.

The Composer plugin now defers automatic setup when neither WordPress Core nor
an existing setup or configuration is present. This lets you install Runtime
first and configure the WordPress project afterwards. It does not generate a
working site by itself. Adding WordPress Core or opting into configuration enables
the usual automatic setup.

Explicit setup commands still validate their requirements and report a missing
required core. Configured projects and existing installations retain that
validation as well; the `require-wp` default remains unchanged.

## Upgrade

Update an existing beta evaluation project to `1.0.0-beta.2` and review its Composer
lockfile. The command name remains `vendor/bin/runtime`; no configuration or
download-lock migration is required for this fix. Follow the
[beta 1 notes](1.0.0-beta.1.md) for the public API and generated-file changes from
0.2. Existing WordPress URLs and web-server routes remain project-owned.

Packagist registration is still pending. Until it is verified, evaluating this
tag requires the public `https://github.com/SymPress/runtime` VCS repository in
the root Composer project. This is not the final Packagist installation check
required for a release candidate or stable V1.

The production and independent migration field trials were waived by the owner.
Automated tests and isolated installation checks do not constitute production
experience.
