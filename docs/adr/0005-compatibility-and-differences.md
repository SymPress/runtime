# ADR 0005: Compatibility and explicit differences

Status: accepted by the project owner on 2026-09-29 with Phase 0 approval.

The feature union stays available. Differences below are scoped behaviors with separate assertions in differential fixtures. Never normalize a failure away merely because upstream has a bug.

| ID | Source behavior / conflict | Proposed decision and preserved capability |
| --- | --- | --- |
| D01 | R/D Config validates lazily and often falls back after invalid input; malformed JSON is silently ignored. | Validate every run before writes, with source paths and option errors. Keep Result and extension validators; a compatibility diagnostic identifies formerly ignored invalid settings. |
| D02 | R content-dev default is symlink, D is auto; null/empty collection defaults differ. | Legacy release profile keeps R defaults; native uses D/work-order defaults. Migration emits explicit values where omitting them would change behavior. |
| D03 | Documentation says opt-in wins, but R/D factory filters skip-config and custom steps first. CLI rejects list plus opt-in names. | Native implements requested opt-in precedence and list combinations; compatibility profile preserves upstream conflict behavior. Cover each combination, not just flag parsing. |
| D04 | VCS position differs between source declaration, effective factory order and the brief. | Native uses the work-order sequence; legacy D runs wpcliconfig then VCS then wpcli. Legacy R keeps its eleven-step automatic sequence and offers the additional VCS capability by explicit selection. See ADR 0001. |
| D05 | WP Starter raw environment prioritizes WP_ENV then WORDPRESS_ENV; WP_ENVIRONMENT_TYPE separately controls canonical mapping. | Native canonical-first selection, with raw legacy name retained for file lookup. Legacy selection stays available; kernel always sees mapped WP_ENVIRONMENT_TYPE. |
| D06 | Env-loaded marker skips primary load but appended loading can still occur; cached values can override real environment. | The marker skips all dotenv parsing. Real environment wins over cache/dump/files. Retain cache, interpolation, appended loading and legacy names; test each override route. |
| D07 | Automatic config regeneration generates new salts each time. R Salter permits length 8..256; D uses 64. | Preserve existing managed salts on regeneration; generate missing salts securely, default 64. Keep configurable Salter behavior as API compatibility. Explicit force does not rotate salts implicitly. |
| D08 | URL downloader accepts any validated URL; Phar hash code falls back to MD5 without SHA512. | HTTPS by default, explicit insecure opt-in, optional SHA256 metadata and production enforcement. Keep local and remote sources. WP-CLI download requires SHA512 and fails closed; current supported PHP has SHA512. |
| D09 | R uses tag stripping and HTML escaping even for secrets; D introduces a separate raw-string filter that adds slashes. | Preserve the respective casts in legacy profiles; native secret values remain byte-exact. Persist a specific per-type expectation, never globally strip escapes in comparisons. |
| D10 | WP Starter deletes package dropin source directories after publishing; this can break symlinks or destroy package contents. | Publish safely and retain sources; transactional replacement, no dangling links. Move-content remains explicitly available. |
| D11 | Source supports ten static dropin filenames; current WordPress has additional entries. | Use the verified current core catalog plus upstream union, including multisite. Unknown dropin support remains via the R option and explicit map. |
| D12 | R global script names are pre-wpstarter/post-wpstarter; brief calls them pre-/post-. D adds halt signals; automatic errors can be swallowed. | Support canonical run names, bare names and legacy aliases. Preserve halt/propagation controls, report aggregate failure with nonzero exit; isolate callback failures as documented. |
| D13 | Generated config imports vendor/autoload.php and upstream/Symfony classes. | The environment parser uses a self-contained bootstrap artifact. Native `wp-config-autoload=false` permits configuration runtime without Composer; `true` restores early project autoload after WordPress's hook API. Both legacy profiles default true and migration records that behavior. Runner extension autoload remains separate. ADR 0006 and ADR 0020; exact `release/early-project-autoload` and `dev/early-project-autoload` differential cases retain upstream hook/class availability. |
| D14 | Legacy constructors/callbacks can require Composer internals. | Preserve equivalent operations through native services, provide adapters where type-compatible, and report concrete PHP rewrites. No false promise that arbitrary Composer-typed callbacks run unchanged; ADR 0004. |
| D15 | Section editors use regex replacement strings that interpret dollar/backslash content. R also repeats identical append/prepend calls and throws on a missing section; D deduplicates by call site and leaves missing sections unchanged. | Resolve the generated target, keep replacement text literal, and consistently use D's call-site deduplication and missing-section no-op behavior. This preserves editable sections while making repeated generation safe. All nineteen sections have explicit R/D differential cases. |
| D16 | DB flags can short-circuit on any existing flag; failure paths can conflict with immutable env writes. R probes DB in selected mode; D limits automatic preflight to full runs. | Keep profile-specific behavior; native enabled preflight runs before selected steps except listing, validates complete externally supplied status, reports unknown separately and writes a consistent result once. Preserve valid/env/exists/installed evaluation order and health checks. |
| D17 | R's wp-cli-files validation map points to the commands-file validator despite a files validator existing. | Implement documented file descriptors and eval-file ordering; capture R's failure as an upstream defect fixture, not as desired behavior. |
| D18 | VCS detection only sees .git directories, HG only recognizes generated marker, SVN only emits guidance. | Preserve all three integrations and add actual worktree/HG/SVN checks. Never report unsupported inspection as a pass. |
| D19 | Global runtime getter differs: R provides getenv filter, D provides wpstarter_getenv(). | Native getter plus both legacy adapters when compatibility is enabled. Emit a deprecation once per used alias per execution, including cache hits. |
| D20 | Existing unmarked files are normally overwritable, and secondary generated files do not consistently use overwrite guard. | Mark generated artifacts, apply prevent-overwrite to all targets; require --force for replacing unmarked user-owned files. Preserve explicit overwrite capability with reviewable diagnostics. |
| D21 | Optional prompts are bypassed in selected mode in D; R asks. | Preserve profile-specific behavior; native selected execution is explicit consent for optional step execution, but never implicit consent to overwrite protected files. Noninteractive ask defaults are recorded in the matrix. |
| D22 | Build ID getter uses getenv while runtime parity asks for both superglobals. | Populate both safe superglobals and explicitly bridge the build-ID constant/process env for kernel fingerprinting. Do not globally enable unsafe HTTP header promotion. |
| D25 | D loops in Filesystem::createDir for the relative environment-example target with env-dir `.`. | Resolve project-relative paths before filesystem writes; reproduce the bounded oracle failure and compare output with its equivalent absolute-root workaround. ADR 0018. |
| D26 | Runtime cache remains stale until explicitly flushed. | Native caches validate recorded source paths, sizes and mtimes, including previously missing override files. Legacy cache semantics and explicit deployment dumps remain available. ADR 0023. |
| D27 | Explicit health configuration scans tables on every setup; file-update constants are not managed. | Native health scans use explicit doctor commands. Native staging/production receives editable Composer-managed defaults, with existing constants preserved. Legacy defaults and health execution remain unchanged. ADR 0025. |
| D28 | Remote downloads have no persistent per-project content lock. | Native downloads pin SHA-256 content identities; explicit update remains possible, and configured hashes still win. Legacy locking is opt-in. ADR 0025. |
| D29 | Request-derived URL defaults and opt-in forwarded scheme can trust an untrusted ingress. | Every profile fails closed without explicit canonical WP_HOME in staging/production. Local/development keeps a validated host fallback. Forwarded HTTPS requires configured IP/CIDR trust and a proxy that replaces forwarded headers. |
| D30 | Unfiltered HTML/uploads and outbound HTTP depend on WordPress defaults or project-specific code. | Native Composer-managed staging/production applies unfiltered-content/upload defaults. Outbound HTTP blocking remains explicit opt-in throughout 1.x, with a narrow core-host fallback when enabled. Existing constants/environment overrides remain supported. ADR 0028. |
| D30 | Runtime caching can serialize real environment overrides and auto can behave as an unconditional enable flag. | Native payloads retain safe file defaults and non-secret interpolation expressions, excluding process-derived and command-derived result bytes from persisted value maps. Unrelated keys remain cached/dumped; dynamic source-chain selectors decline persistence. Auto checks writable parents before shutdown; explicit native true requires writable new-cache storage. Legacy boolean behavior is retained. |

Compatibility is enabled by default for legacy detection and independently switchable off. It is not a dependency on wecodemore. Use native names internally. Migration reads without executing PHP command providers; it writes a new config atomically, retains the original, refuses conflicting targets unless forced and lists exact source locations needing PHP changes. A second migration is a no-op.

Resolve `unknown-dropins`, deprecated skip-db-check, defaults and path bases before converting. Never silently rewrite the demo's `../dev-ops/orchestrate.php` to a different file. Runtime deprecations go to the configured diagnostic channel, not HTTP output containing secrets. Hook aliases are dispatched in documented legacy-then-native order so the native policy can be authoritative; both receive the same raw environment parameter.
